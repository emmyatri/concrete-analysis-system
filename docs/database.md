# Database Documentation

## Development Setup

The following is for those who wish to manage migrations via the command line. The app automatically applies existing migrations so there is no need to manage them otherwise.

### Installing the Migration Tool

```bash
dotnet install --global dotnet-ef
```

> Make sure the tools directory is on your PATH:
> * linux: PATH=\$PATH:\$HOME/.dotnet/tools
> * windows: see https://stackoverflow.com/a/56876020

### Creating a Migration

```bash
# from repository root
dotnet ef migrations add InitialCreate --project src/Vulcan.Infrastructure --startup-project src/Vulcan.Api
```

*Why?* Infrastructure is the source of configuration and where migrations are stored. Api is the runtime project where the database is initialized.

### Deleting the Latest Migration

```bash
dotnet ef migrations remove --project src/Vulcan.Infrastructure --startup-project src/Vulcan.Api
```


## Sqlite Constraints

Sqlite has several limitations in terms of typing.

1. No decimal data type
2. No boolean data type
3. No datetime data type

Although, Entity Framework Core handles the mapping automatically:

1. Decimals are stored as TEXT
2. Booleans are stored as INTEGER
3. Datetimes are stored as TEXT

This can be observed below, in a migration generated by EF: *taken from the initial migration*
```csharp
{
    // ...
    MixWaterPh = table.Column<decimal>(type: "TEXT", nullable: false),
    IsSynthetic = table.Column<bool>(type: "INTEGER", nullable: false),
    CreatedAtUtc = table.Column<DateTime>(type: "TEXT", nullable: false),
    // ...
}
```

By convention, we mitigate this constraint by handling calculations in code.
